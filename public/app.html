Chatbot Flows

              
Automate WhatsApp conversations: greet customers, answer common questions, collect details and hand over to your team.

            

            
          

          

          

            

              
FlowStarts whenNumbersStartedFinishedHanded overLive

              
            

          

          

            
How flows work

            
    
              
  • Keyword flows start when a message contains a keyword, even during a chat with your team.
    • 
              
  • First message and Any message flows don't start while the customer has an open ticket, so they never interrupt your team.
    • 
              
  • While a flow is running, the customer's replies go to the bot instead of creating tickets. Hand to a person creates a ticket with everything the bot collected.
    • 
              
  • Answers to questions are saved on the contact. You can use them in later messages and campaigns, e.g. {{email}}.
    • 
              
  • Replying STOP always ends the flow and unsubscribes the contact.
    •

How to avoid getting blocked

            
    
              
  1. Only message people who said yes. Collect opt-in (website form, checkout tick box, "Send us a WhatsApp" link). Never use bought or scraped lists.
    2. 
              
  2. Get customers to message you first. Chats started by the customer are almost never reported. Put a click-to-chat link and QR code on your website, invoices and shop.
    3. 
              
  3. Warm up every new number. Use it for normal chats for a week, then grow volume slowly. Keep warm-up mode on.
    4. 
              
  4. Make each message personal. Use {{name}} and {Hi|Hello} variations, and send offers that match the contact's tags.
    5. 
              
  5. Always offer an exit. End marketing messages with "Reply STOP to unsubscribe". A STOP is much better than a Block.
    6. 
              
  6. Start conversations, not broadcasts. Ask a question or add quick-reply buttons so people answer. Replies build trust.
    7. 
              
  7. Reply fast. Answer incoming chats from the Tickets screen; active two-way chats look like a real business.
    8. 
              
  8. Complete your WhatsApp Business profile with logo, business name, description, address and website.
    9. 
              
  9. Keep your main number safe. Run campaigns from separate numbers and spread volume across them.
    10. 
              
  10. Logged out unexpectedly? Stop all campaigns for 48 hours and use the number only for normal chats.
    11. 
              
  11. For large volumes, use the official WhatsApp Business Cloud API, which is designed for bulk marketing.
    12.

API Docs

        

          
Base URL:  · Auth header: x-api-key: wak_...

          
Send text


POST /api/messages/text
{ "sessionId": "sales-1", "to": "919876543210", "text": "Hello!" }

          
Send media


POST /api/messages/media
{ "sessionId": "sales-1", "to": "919876543210",
  "mediaUrl": "https://example.com/offer.jpg", "caption": "Offer" }
# or multipart/form-data with fields sessionId, to, caption + file

          
Send image + buttons


POST /api/messages/buttons
{ "sessionId": "sales-1", "to": "919876543210",
  "text": "Diwali offer: 30% off!", "footer": "Acme Store",
  "imageUrl": "https://example.com/offer.jpg",
  "buttons": [
    { "type": "reply", "title": "See prices", "reply": "Plans start at ₹499/month" },
    { "type": "url",   "title": "Shop now",   "url": "https://shop.example.com" },
    { "type": "call",  "title": "Call us",    "phone": "919876543210" }
  ] }
# types: reply | url | call | copy ("code"). Max 3 buttons, titles max 20 characters.
# "reply" is optional: sent automatically when the customer taps the button or replies with its number.
# multipart/form-data also works: "image" file + "buttons" as a JSON string.
# Incoming taps arrive in the message.received webhook with "button": { "id", "title" }.

          
Campaigns accept the same "buttons" and "footer" fields (image from "mediaUrl").

          
Check number


GET /api/check/:sessionId/:phone   →  { "exists": true }

          
Sessions


GET    /api/sessions
POST   /api/sessions            { "id": "sales-1" }
GET    /api/sessions/:id/qr     (?format=image for PNG)
DELETE /api/sessions/:id        (?logout=true to unlink device)

          
Contacts


GET    /api/contacts?tag=vip&q=rahul
POST   /api/contacts            { "phone": "...", "name": "...", "tags": ["vip"] }  (or an array)
POST   /api/contacts/import     multipart "file" (CSV: phone,name,tags)
PATCH  /api/contacts/:id        { "optedOut": true }
DELETE /api/contacts/:id

          
Campaigns


POST /api/campaigns
{ "name": "Diwali", "sessionId": "sales-1", "tags": ["vip"],
  "message": "Hi {{name}} ... Reply STOP to unsubscribe", "mediaUrl": null, "startNow": true }
# or "phones": ["9198...", ...] instead of tags
GET  /api/campaigns   |   GET /api/campaigns/:id
POST /api/campaigns/:id/start   |   POST /api/campaigns/:id/pause

          
Tickets


GET    /api/tickets?status=open,pending&priority=&assignee=<name>|none&q=&sort=updated|priority
GET    /api/tickets/stats
GET    /api/tickets/:id            (id or ticket number, e.g. 1001) — includes full thread
POST   /api/tickets                { "sessionId", "phone", "name", "subject", "priority",
                                     "message", "sendMessage": true, "by": "Agent name" }
PATCH  /api/tickets/:id            { "status": "open|pending|resolved|closed", "priority",
                                     "assignee", "subject", "tags", "notify": true, "by" }
POST   /api/tickets/:id/reply      { "text": "...", "by": "Agent name" }  (or multipart with "file")
POST   /api/tickets/:id/notes      { "text": "internal note", "by": "Agent name" }
POST   /api/tickets/:id/read       mark as read
DELETE /api/tickets/:id

          
API keys act with admin rights. Pass "by": "Name" in ticket requests to record who acted.
          Tickets also accept "departmentId" (omit it to use the routing rules); assignee is a user id.

          
Users & departments


GET    /api/users/directory        active users (id, name, role, departmentIds)
GET    /api/users                  (admin)
POST   /api/users                  { "name", "username", "password", "role": "agent|manager|admin", "departmentIds": [] }
PATCH  /api/users/:id              { "name", "role", "departmentIds", "active", "password" }
DELETE /api/users/:id
GET    /api/departments
POST   /api/departments            { "name", "description", "sessionIds": [], "keywords": [],
                                     "autoAssign": true, "isDefault": false }
PATCH  /api/departments/:id  |  DELETE /api/departments/:id
POST   /api/auth/login             { "username", "password" } → { "token", "user" }  (Bearer token, 12 h)

          
Incoming WhatsApp messages open a ticket automatically, or continue the customer's latest open ticket.
          Webhook events: ticket.created, ticket.updated, ticket.message.
